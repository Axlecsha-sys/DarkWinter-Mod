# Selected forest-food plants

Selected by the user: cattail R2, rhizome K2, juniper M1, cranberry C2,
lingonberry **B2 shape with B3 bronze colour**, wild rose S2.
The original concept sheets and the task snapshot are preserved here.

This stage contains models and original painted textures. It does not implement
gathering, food values, crafting, seasonal changes or biome spawning.

`tools/forest_food_models.py --apply` authors only the ten selected catalogue IDs.
It does not run the global furniture generator or replace previous models.
The four `_no_berries` entries use exactly the same foliage, branches, UVs,
materials and snow as their fruiting counterparts. Only tagged fruit/calyx faces
are removed. `tools/check-forest-food.py` verifies this and old-asset preservation.

The original texture atlases were painted with imagegen. Production copies are
uniform 50% reductions to 768×512, with no retouching or procedural noise fill.
The dry atlas is a 3×2 grid; the shrub atlas is a 4×2 grid. Material aliases and
guarded tile UVs are declared in `SLOTS` in the authoring tool. Fruitless versions
share the leaf tiles exactly and never reference the fruit tiles in their mesh.

Meshes use the existing resource-pack-aware chunk and whole-item path. They
add no block entities, ticking or custom world renderer. The ten assets have a
separate 30000-face allocation and keep the existing 5000-face per-object limit;
old family limits remain fixed. This is a static resource bound, not an FPS claim.

The wild rose owns a 2×2 horizontal, two-cell-high footprint for its broad crown;
the cattail owns two vertical cells. Plant collision is empty.

Native client fixture: `runForestFoodClientTest`; comparison page is generated by
`tools/forest_food_review.py` under `build/forest-food-implementation-v1`.
The fixture uses an isolated disposable world with fixed cameras, paired lighting
and neutral backdrops. Source screenshots remain unmodified. Previous user saves
are never opened by this fixture.

Technical validation is complete. Artistic acceptance remains with the user.
