# DVCPP-001: геометрия и чтение освещения

Текущий этап укрепляет существующий эксперимент с финальной записью вершин. Он не заменяет модельный сборщик и не доказывает ускорение всей игры. Публичный default остаётся VANILLA.

## Подробные таймеры

На каждом enqueue раньше выполнялась пара nanoTime, в том числе вокруг копирования 128 bytes Indigo. Теперь component clocks включаются только startup property `darkwinter.mesh.detailedTiming=true`. По умолчанию они исключены из пути упаковки; полное compile wall измеряется по-прежнему. Недоступные компоненты записываются как -1/UNAVAILABLE. Флаг присутствует в report и metadata/configHash.

Проверено сохранение byte/layout, native calls, fallback и ownership. Примитивный VertexConsumer hook не заменялся без доказательства выигрыша; отдельный Indigo hook сохранён. Сложная схема прямой native staging/promotion не включена: полный packet prototype оказался медленнее компактного Java writer на выбранных размерах.

## Фактические проверки

- Standalone blockMeshVerify: 640 template/Indigo packets, физические guards, sequential/concurrent byte oracle; PASS.
- Private staging experiment: 40405 assertions, включая повторное использование изменяемого Indigo emitter, retire между enqueue/flush, Java repair и четыре независимых worker; PASS. Его microbenchmark исключает model/light/reserve/GPU и не считается FPS.
- Четыре настоящих Vulkan-клиента в порядке OFF→ON→ON→OFF. Восемь кампаний, 480 измеренных компиляций, по 80 на каждый writer и состояние таймеров; с контролем/прогревом — 704 replay-компиляции.
- Совпали записанные hashes пяти Java-файлов, DLL, исходного level.dat и вершин четырёх выбранных секций. Draw/visibility/block entities и GPU upload readiness корректны. На секцию 9472 грани; в каждой кампании CPP выполнил 200 native batches без fallback.

## Профиль настоящих работников Vulkan

Дополнительно записан JFR реальной асинхронной сборки с priority NONE, без replay-перехвата обычных задач. Две сцены, 32 волны allChanged на сцену, четыре целевые секции: все 256 целевых компиляций завершились. В записи 6543 compile scopes, незавершённых/ошибочных scopes и JFR DataLoss нет. Отдельные replay-кампании сохранили точное совпадение геометрии VANILLA/JAVA_PACKED/CPP_PACKED.

Внутри подтверждённых ordinary worker scopes получены 295 Java samples для каменного checkerboard и 660 для смешанной сцены с tint/листвой/оградой. Inclusive samples AO — 157/271, computeFace — 136/239, lightCoords — 85/118. Эти стеки вложены друг в друга, поэтому числа нельзя складывать или выдавать за доли CPU. Exclusive samples финального writer — только 1/7. На этой записи первоочередная цель находится до упаковки вершин.

Частый листовой RegularImmutableMap.get встречается в 25/179 samples; проверенные стеки ведут к ClientLevel.getUncachedNoiseBiome и registry lookup. Но allChanged очищает tint caches: это профиль холодных данных. Холодный tint сам по себе не означает отсутствующий biome chunk. В четырёх тёплых/холодных контрольных матрицах все 640 настоящих worker-компиляций завершились с нулём fallback-вызовов и registry lookups. Простой cache этого getter не является доказанным ускорением обычной сборки и в production не включён.

## Пакетный AO перед writer, 2 ноября

C++17-прототип вычисляет внутренние значения Indigo computeFace пакетами по подготовленным light/shade/flags. Обычные модели, tint, внешний 72-entry AO cache и writer сохранены. Поддерживаются восемь явно выбранных семейств непрозрачных кубов; сложная геометрия остаётся на штатном пути. Для сравнения добавлен Java-вариант с ленивым кэшем raw brightness и shade по позиции/состоянию. Оба варианта находятся только в приватном стенде, публичный default не изменён.

Отдельный оракул сопоставил raw AO/light words с настоящим Indigo: 362529 assertions, 20 native calls, PASS. Проверены границы полного 18³ halo, входные/выходные guards, lifetime FFM и независимые worker arenas. Client light snapshot использует опубликованные COW-слои, копии затронутых DataLayer и верхние метаданные skylight. На baseline, источнике, удалении источника/открытии неба и удалённом обновлении сравнивались 34992 позиции; также пройдены пять uniform/absent engine-контрактов. Изменение далёкой карты не инвалидирует локальный набор чтения. Это не атомарный снимок двух световых каналов и не гарантия свежести будущей публикации.

Затем выполнены два настоящих Vulkan-клиента с обратным порядком вариантов. На асинхронном SectionCompiler worker сохранён original primary; отдельно повторяется неизменённое тело native compiler на одном независимом SectionBufferBuilderPack для всех режимов. Только primary возвращается игровому caller. Таймер включает контекст, снимок/свойства, FFM, native kernel, readback, исходную сборку, применение значений и финальную проверку/закрытие. Совпали полные vertex/index bytes, draw state, 36 пар видимости, translucency centroid bits и прямые identities/type/position блок-сущностей. ## Кэш чтения освещения секций

`SectionLightCache` хранит raw light и побитовые значения shade в шести примитивных массивах. Записи содержат полный 64-битный ключ и поколение; коллизия даёт промах и штатное вычисление. Startup-параметр `darkwinter.render.sectionLightCacheSlots` допускает 1024, 2048 и 8192 записи в каждом наборе: 32, 64 и 256 КиБ примитивного содержимого на созданный worker Cache. Значение по умолчанию и fallback для неподдержанного параметра — 1024. Заголовки объектов и исходные карты в эту оценку не входят. Ссылок на мир, чанки или модели нет; поколение сбрасывается при начале и завершении compile scope.

Mixin меняет четыре примитивных get/put в `BlockModelLighter.Cache`. Вычисления света, emission, disabled-ветки и формирование вершин сохранены. При `-Ddarkwinter.render.sectionLightCache=false` массивы не создаются, используются исходные карты. Состояние режима, число записей и расчётный payload входят в метаданные и configHash DV032.

Предварительный replay уменьшил объединённые медианы ORIGINAL на 5,29% для плотного камня, 22,60% для checker и 27,50% для смешанной сцены. Отдельное расширение нативных FIFO-карт со 100 до 6144 элементов отклонено: плотный камень стал медленнее на 7,38%.

На запуск приходится 96 измеренных worker-компиляций и три записи DV032 по 8 секунд. Полная геометрия, свет, биомы и block IDs сравниваются вне записи.

Это ограничение наблюдателя, а не новый протокол публикации света.

## Размер массива и двухуровневая схема

Промежуточный вариант FIFO100→direct8192 проверен отдельно четырьмя JVM. Он сохранил геометрию, но увеличил объединённую медиану плотного камня с 1,70805 до 2,22810 мс (+30,45%). У checker и смешанных моделей сокращение составило 7,67% и 7,13%. Эта схема отклонена; L1-код и его параметр отсутствуют в итоговой реализации.

Итоговый прямой кэш допускает ограниченные размеры 1024, 2048 и 8192. Дополнительные шесть JVM выполнены в порядке native→1024→2048→2048→1024→native. Таймер охватывает настоящий compiler body, без replay. Пара System timestamp непосредственно до/после старта capture позволяет численно проверить принадлежность всех worker scopes; native публикация проверяется отдельно по Util timestamp.

## Естественный мир и генерация новых чанков

Для source identity `95228e7c8e33bf925257170c0cff8757c4fe9f626e430ec2d94c455f0453798f` выполнены две серии OFF→ON2048→ON2048→OFF. Условия: Vulkan, 2560×1440, RD15/SD17, Java 25, ZGC 4 ГиБ, RX 7600 XT.

На сохранённой местности записаны 42406 кадров, 5308 GPU-замеров и 3421 compiler scope. Статика и обычный полёт проверены без эффектов и со снегом/атмосферой/постобработкой.
