# Самостоятельное ядро: DarkWinter_Test и изменение мира

Актуальное ускорение иерархии описано в [этапе 4](CORE_STAGE4_RU.md). Возможности и ограничения мира ниже сохраняются.

Дата: 06.11.2026. Продолжение этапа 2, Windows x64, Vulkan, C++20.

## Результат и запуск

Start-DarkWinter-Core.cmd открывает build/core/world-client/DarkWinter.exe.
Новый клиент работает без JVM, Java GC, Fabric и встроенного MinecraftServer.
Обычный Fabric build сохраняет свой игровой конвейер.

В клиенте есть исходный участок DarkWinter_Test, меню и пауза с исходными
фонами/wordmark/шрифтом мода, HUD времени, палитра материалов, удаление и
установка блоков, сохранение и открытие собственного мира.
Полный инвентарь, остальные HUD и механики выживания пока остаются в моде.
См. native/darkwinter-client/README_WORLD_RU.txt для управления.

Это конечный участок 96 × 96 блоков, высоты [48,160): 252 секции,
170 состояний, 635 шаблонов, 252547 общих треугольников, 30 текстур.
Мир создан настоящим генератором фиксированного darkwinter:darkwinter_test,
seed19021. Формы извлечены из текущих BlockStateModel без отсечения граней
соседями, вместе с контекстными вариантами ветвей/снега и реальными UV.
Из ванильного атласа берутся только использованные изображения, не полный атлас.

Minecraft запускается только отдельным заданием экспорта. Он не входит в
процесс самостоятельного клиента. Бесконечная нативная генерация ещё не написана.

## Конвейер правки

Логическое состояние секции заменяется неизменяемым снимком с новой ревизией.
Тяжёлая подготовка выполняется пулом из четырёх C++-потоков.
Данные для задач неизменяемы; одновременно удерживается одна пакетная подготовка.
Повторные правки объединяются. Результат с устаревшей ревизией отбрасывается.

Непустые ячейки формы могут выходить за границу блока: у фактических моделей
координаты от -1,2149248 до 1,897615. Маски владельцев указывают, формы каких
соседних блоков пересекают данную ячейку. Иерархия занятости строится по этим
маскам, поэтому хвоя в соседней воздушной ячейке не исчезает.
Начальное построение этих масок также выполняется пулом.

Правка затрагивает секции в пределах максимального выноса модели. На GPU
передаются только изменённые массивы ячеек, масок и занятости этих секций.
Шаблоны форм и текстуры остаются общими. Патчи сохраняют собственные копии
опубликованных данных: следующая логическая правка не меняет ещё не отправленный
патч. Два кадра используют отдельные staging-буферы; барьеры очереди защищают
общий мир между чтением шейдера и обновлением. DeviceWaitIdle в обычной правке нет.

Тени допускают раннее завершение после первого непрозрачного препятствия.
Непрозрачные текстуры не читаются повторно для проверки alpha cutout.
Это обоснованные сокращения работы, не гарантия FPS всей игры.

## Сохранение и форматы

DWV v1 остаётся форматом логических блоков. DWA v2 привязан к палитре DWV,
а не к хешу целого файла: изменения блоков не делают шаблоны несовместимыми.
Контрольные суммы и диапазоны проверяются перед использованием.
DWA v1 дорожного прототипа продолжает читаться.

Сохранение создаёт новый DWV и STATE с хешем логических блоков, камерой и
игровым временем. STATE публикуется переименованием временного файла после DWV.
«Продолжить» выбирает последнее опубликованное сохранение.
Исходный world.dwv не перезаписывается. Это не гарантия сохранности при
отключении питания; fsync и восстановление повреждённых файлов ещё не реализованы.

Контекстные формы исходного участка берутся из экспорта; новый блок получает
шаблон своего состояния. Полные правила соседних соединений Minecraft пока
не перенесены, поэтому окружающие ветви/снежные стыки не меняют форму автоматически.
Вода представлена объёмом реальной высоты FluidState и исходной still-текстурой.
Движение жидкости, анимация, преломление и точные угловые высоты течения отсутствуют.

## Проверка

coreVerifyWorld проверяет изменение мира, очередь с устаревшей задачей,
восстановление после серии правок, сохранение/загрузку, интерфейс, движение
клавишами и изменение размера окна. Попадания GPU сравниваются с независимым
перебором треугольников CPU на двух видах леса.

Для совпадающих поверхностей установлен одинаковый порядок выбора материала.
На численно неоднозначных границах alpha-текселей CPU помечает луч отдельно;
такие лучи не засчитываются в строгие совпадения. Их число явно записывается
в oracleAmbiguous. Остальные лучи требуют совпадения материала и расстояния.
Это учитывает чувствительность nearest alpha к округлению float, не позволяет
расхождениям вне этих границ проходить проверку.

coreAuditWorld запускает отдельный процесс с PATH только Windows System32
и без JAVA_HOME/JDK, проверяет список модулей, пять повреждённых входов,
неизменность исходных файлов, git diff --check, игнорирование исходников,
CRC архива и хеши файлов. Измерения относятся только к dispatch GPU, одной
сцене и выбранной камере. Vulkan validation layers в окружении отсутствуют,
драйверные оверлеи остаются; это не сравнение с Minecraft.

Последние результаты: build/core/latest-world.json и latest-world-audit.json.
Снимки и подробные JSON находятся в указанных ими каталогах.

## Воспроизведение

Закрыть самостоятельный клиент перед пересборкой EXE.

~~~powershell
.\gradlew.bat coreExportBiome
.\gradlew.bat coreVerifyWorld
.\gradlew.bat coreAuditWorld
.\gradlew.bat coreRunWorld
~~~

Обычный build не зависит от этих задач. Экспорт требует текущую среду
Fabric/Minecraft/JDK25, сборка EXE — проверенный Zig0.14.1 и заголовки
Vulkan1.3.296. Запуск готового EXE требует только Windows и драйвер Vulkan.

Полного DAG мира, симуляции персонажа, столкновений и стриминга большого
мира пока нет. Последовательные события окна и отправка GPU-команд остаются
частью управления кадром; тяжёлая обработка секций выполняется параллельно.
