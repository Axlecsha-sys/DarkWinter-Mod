# DV-019: упаковка палитр и паузы GC

Первый адресный этап устраняет временные массивы в native PalettedContainer.pack. Полное устранение микрофризов или всех пауз GC не подтверждено. Работа дополняет [DV-011](DV_011_RU.md), который ограничивает подготовку снимков и переносит первоначальную сборку новых секций в workers.

## Изменение

Native reencodeContents создавал int[4096] для однородной блоковой секции или int[64] для биомов. При единственном значении итоговый zero-bit PackedData этот массив отбрасывает.

SingleValuePalettePacking сокращает только этот случай: точный класс ZeroBitStorage, положительный размер, одно старое значение и пустая новая палитра. Единственное значение переносится штатным idFor, промежуточный массив заменяется общим пустым. Native Strategy для блоков/биомов выбирает zero-bit формат и не читает этот массив.

Mixin оборачивает только вызов reencodeContents из pack. Native acquire/try/finally/release, PackedData, codec и NBT не меняются. Смешанные и исторически расширенные палитры, несовместимые классы и другие случаи используют прежний путь.

## Проверки

Настоящий преобразованный pack сравнивается с native-контролем в том же JVM; приватный bypass отключает только shortcut. Десять групп проверяют AIR/STONE на 4096 ячеек, биомы на 64, смешанные данные, широкую палитру после возврата к одному значению, ограничения и исключения. Сравниваются PackedData, codec roundtrip, NBT и двоичные данные. Исключение внутри native try проверяет освобождение guard через finally. Подкласс ZeroBitStorage и общий пустой scratch проверены отдельно.

SerializableChunkData.copyOf реального FULL-чанка дал одинаковый полный NBT и двоичный результат: 24 секции, 48 вызовов pack, 44 сокращённых пути, четыре heightmap. В этом чанке нет block entities: живой сундук с инвентарём и повторное открытие этого файла с диска здесь не заявляются.

Каждый успешный native прогон проходит также 14 geometry-проверок DV-011: deferred dirty, приоритет правки игрока, byte parity и solid→EMPTY→solid через workers/GPU. Используются отдельные копии стенда.

В прогретом чередующемся контроле приблизительный JDK thread allocation counter показал:

| Однородный контейнер | Native контроль | Shortcut |
| --- | ---: | ---: |
| Блоки, 4096 ячеек | 16 864 B/операцию | 456 B/операцию |
| Биомы, 64 ячейки | 730,30 B/операцию | 444 B/операцию |

Приватный bypass/наблюдение включены в счётчик, JIT влияет на раунды. Это не точный размер каждой production операции. Устранение int[4096]/int[64] подтверждено также исходниками и отдельными JFR фазами. Количество route allocation samples со стеком reencodeContents сократилось с 505 до 20; это выборочные события, а не число всех объектов или точный объём памяти.

## Задержки и настройка запуска

Источник flat-стенда содержит 100 000 origins. Дополнительный контроль начинается с пустой provenance в свежей копии до открытия мира; исходный SHA-256 и остальные файлы сохранены, Undo/Redo пусты. Во всех сопоставленных маршрутах доставлено 709 новых координат и скомпилированы одинаковые 424 секции.

После изменения остаются G1-паузы: ранняя запись содержит young pause 99,697 мс внутри кадра 106,521 мс и отдельную CodeCache GC Threshold pause. Одного сокращения массивов недостаточно.

На RX 7600 XT / Java 25.0.4.1 отдельно сравнивались G1 и ZGC при одинаковом heap 4 GiB, без изменения production кода. Условия: 30 секунд, шесть перемещений, 1280×720, FOV 70, дальность 8, NEARBY, 140 FPS, без VSync/F10/модулей.

Общие метки связывают реальные кадры, tick/render, GPU submit/fence, present, limiter и JFR; счётчики совпадают, потерь нет. Окно в фокусе, не свёрнуто, throttle NONE. В G1/Vulkan худший кадр содержит GC pause 26,583 мс; другой — 20,834 мс. В ZGC/Vulkan пики включают 23,536 и 15,775 мс native DXGI present, без пересечений с GC-паузами.

Ранний ZGC/OpenGL повтор дал 147,334 мс и 29 кадров >33 мс. У 18 есть native stack sample в glClientWaitSync, но нет пересечения с GC-паузой. Подробные повторы это не воспроизвели. Причина GPU-ожидания остаётся неустановленной, запись не исключается из оценки. Универсальное превосходство ZGC и отсутствие всех задержек не заявляются.

Native OpenGL уже передаёт GL_SYNC_FLUSH_COMMANDS_BIT. GPU fence/present не изменяются: преждевременное переиспользование transient memory небезопасно. Pipeline Guard, shaders/sky/fog, движение, календарь и погода этим этапом не редактируются.

## Необязательный локальный профиль

gradle/client-runtime.gradle читает run/config/darkwinter/client-runtime.properties только для штатного runClient. Без файла дополнительные JVM/backend flags не добавляются. Файл игнорируется Git и не входит в JAR.

Локально на проверенном ПК выбран gc=zgc, heap=4G, backend=VULKAN. Свойства darkwinter.clientGc, darkwinter.clientHeap и darkwinter.graphicsBackend переопределяют файл по наличию, включая пустой heap. Допускаются только известные значения и размер heap; конфликтующие flags отклоняются без вывода окружения.

Профиль не меняет daemon, dedicated server или приватные тестовые JVM. JAR не может заменить GC уже запущенной Java: для внешнего лаунчера параметры задаются отдельно. Это локальная обратимая настройка, а не общий default или исправление драйвера.
