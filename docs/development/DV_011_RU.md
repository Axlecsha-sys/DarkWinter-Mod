# DV-011: подготовка снимков и пустые секции

Адресный этап ограничивает подготовку геометрии за один проход extraction, переносит первоначальную сборку новых секций в native workers и исключает полный обход заведомо пустого снимка. Частичная перестройка непустой секции здесь не реализована. Полное устранение микрофризов этим этапом не подтверждено.

## Изменения

LevelExtractor раньше создавал RenderSectionRegion для каждой подходящей dirty-секции до применения бюджета compileSync из DV-017. Один регион включает 27 соседних SectionCopy. Теперь подготовка получает мягкий бюджет 2 мс и максимум восемь обычных снимков за extraction; ещё два места зарезервированы для изменений игрока. Первая обычная работа допускается даже при исчерпанном времени, чтобы сохранялось продвижение. Крупная неделимая операция и зарезервированные работы могут превысить мягкий бюджет.

Отложенные секции не попадают в sectionUpdateRenderStates и не вызывают native setNotDirty. До допуска новые изменения накапливаются в прежнем dirty-состоянии; снимок создаётся по актуальному состоянию мира. Сохраняются проверка соседей, native cache в пределах одного прохода, последующая компиляция, отмена и загрузка GPU. Между кадрами RenderRegionCache не сохраняется.

Для extraction используется повторно применяемый список ссылок на видимые секции. Исходный список LevelRenderer не меняется, временные ссылки очищаются после extraction. Курсор следующего прохода перемещается после первого допущенного элемента. Для стабильного списка постоянно подходящих dirty-секций каждый элемент становится первым не позднее N проходов; для меняющейся видимости или отсутствующих соседей такой срок не заявляется. Приоритет native worker queue по расстоянию остаётся прежним.

Изначально только UNCOMPILED без playerChanged направлялся из compileSync в compileAsync. Текущий маршрут DV-017 по умолчанию направляет все подготовленные секции в native workers, включая изменения игрока. Бюджет и резерв снимков extraction остаются прежними; явного отдельного player-priority у native compileAsync нет. Приведённые ниже исторические измерения описывают первоначальный этап и не заменяют проверку нового маршрута.

SectionCopy уже хранит null вместо палитры для пустого снимка. EmptySectionCompiler проверяет центральную копию, соответствие координат и отсутствие debug-режима. Только тогда возвращается пустой native Results с полностью открытой видимостью, без обхода 4096 ячеек. Непустые снимки, debug и несовпадающий центр проходят прежний компилятор. Текущий mutable мир для решения о пустоте не опрашивается.

## Native маршрут

Обычный Minecraft 26.3 / Fabric / Java 25, RX 7600 XT. Отдельные копии одного flat save; шесть перемещений через пять секунд по x=8192…8512, z=8, y=-44. Камера и настройки фиксированы: 1280×720, FOV 70, render distance 8, NEARBY, native лимит 140 FPS, без VSync, F10 и модулей лаборатории. Перед стартом проверены отсутствие сохранённых/загруженных центров маршрута и нормальная незамороженная серверная симуляция. Генерация мира и доставка packets включены.

Интервалы снимаются только в фактической точке DebugScreenOverlay.logFrameDuration. Холостые возвраты renderFrame не считаются кадрами. Измеряются packet processing, client tick, pollLightUpdates, extraction, createRegion, sync compile и upload. SETTLE включает проверяющий обход геометрии и используется только для проверки завершения.

Все очереди и выполняющиеся задачи завершились, видимые dirty-секции обработаны, GPU-срезы готовы. Общий выигрыш плавности на этом маршруте не обнаружен: разница p99 около 0,002 мс не является доказательством ускорения.

В маршруте не было пустых результатов компилятора. Поэтому его статистика не доказывает производительный эффект empty-shortcut; этот эффект проверяется отдельно точным числом обращений к снимку.

## Проверки корректности

В каждом native backend прошли 14 проверок:

- Настоящий burst из 13 уже видимых непустых готовых секций: 12 обычных и поздняя в порядке секция игрока. OpenGL допустил 8 обычных и одну player-секцию первым проходом, оставил четыре dirty-флага и обработал остаток следующим проходом. Player-секция действительно вызвала compileSync в первом batch; все 13 новых meshes получили GPU-срезы с прежними draws/visibility.
- Десять differential-случаев вызывают преобразованный SectionCompiler дважды на одном настоящем неизменяемом регионе. Приватный ThreadLocal отключает shortcut только для native-контроля. Сравниваются все байты вершин и индексов, draw states, 36 пар видимости, block entities и состояние сортировки прозрачности.
- Для пустого центра, пустого центра с непрозрачными соседями и старого пустого снимка после live-изменения реальный обход сокращён с 4096 чтений до нуля. Камень, стекло, листва, вода, сундук, несовпадающий центр и debug-снимок сохраняют native fallback.
- Цикл solid→EMPTY→solid проходит настоящие worker tasks и публикацию с проверкой GPU-срезов.

Debug-случай использует флаг настоящих SectionCopy в приватном стенде; отдельное сохранение debug-generator не открывалось.

Учёт посещённых секций использует прямой результат native getDirtyState без упаковки long в Long при каждом обходе. Состояние dirty и локальные переменные native вызова сохраняются.

Политика бюджета отдельно прошла 12 детерминированных сценариев и 38 243 assertions, включая границу времени, переполнение nanoTime, резерв игрока и 256 воспроизводимых комбинаций стабильного списка. Это проверка фактического helper, а не самостоятельная копия алгоритма.

Дополнительно повторены существующие DV-017 lifecycle-проверки на OpenGL и Vulkan: по 18 bursts, все 16 lifecycle-строк PASS, отменённый старый EMPTY не публикуется, reuse/reload и реальные правки в центре/углу секции проходят. Два OIT pixel-control в каждом backend дали нулевую разницу RGB. Эти lifecycle-прогоны выполнены до замены технического перехвата счётчика обхода; финальный native route/burst/differential повторён на обоих backend после неё. SDK-времена и внутренние before/after режимы прежнего sync-бюджета не используются как A/B-доказательство DV-011.

## GC и границы вывода

Два худших кадра OpenGL before совпадают с G1 New pauses 24,059 и 17,317 мс. В финальном OpenGL after сохраняются G1 New pauses 23,473 и 22,789 мс. Отдельный extraction-span 26,540 мс с нулём snapshots/новых чанков не совпал с записанными GC, park или monitor events; его причина не установлена. Длительность concurrent G1 Old cycle не приравнивается к паузе всей игры.

В финальной записи Vulkan есть один интервал 42,655 мс; внутри него зарегистрирована G1 New pause 39,016 мс, без новых чанков, snapshots или sync compile в этом кадре. Отдельный extraction-span 14,061 мс остаётся без установленной причины. Vulkan before не записывался, поэтому межверсионное сравнение Vulkan не заявляется. Устранение этих пиков не подтверждено; отдельный анализ крупных выделений продолжается. Источник копии содержит 100 000 origins, которые загружаются и удаляются до прогрева. Две секунды покоя не доказывают отсутствие их последующего влияния на GC. Для определения места крупных выделений и отдельного контроля с пустой provenance проводится дополнительная диагностика; она не считается исправлением production GC или сопоставимым A/B-замером.

Полная инкрементальная геометрия непустых секций, другая местность, длительная статистика, иное оборудование и полное устранение GC-пауз остаются открытыми. GPU-upload не прерывается посередине native batch, JVM/GC flags не менялись. Pipeline Guard, текущие shaders/sky/fog, движение, календарь и погода не редактировались.

## Публикация после отмены и переноса секции

Исправлен отдельный дефект штатной загрузки непустой геометрии: результат уже завершённой компиляции оставался в очереди GPU после отмены задачи. Поздний callback мог заменить более новый mesh и закрыть его данные. Проверка только пустых результатов не покрывала эту ветку.

`SectionMeshPublication` связывает результат с исходной координатой, поколением секции и флагом отмены. До обращения к картам загрузки проверяется актуальность результата; непосредственно перед публикацией проверка повторяется под тем же монитором, что и отмена. Устаревший результат освобождает только собственные native allocation keys и только один раз. Текущий mesh остаётся видимым до нормальной замены; сортировка его прозрачности сохраняется.

Токен содержит слабые ссылки на задачу и владельца. Дополнительного сильного удержания `CompileTask.region` и снимков соседних секций нет. Очереди, алгоритм meshing, форматы GPU-буферов и fence/barrier-порядок не заменяются.

Дефект воспроизведён на действительных классах Minecraft 26.3, включая порядок native staged-map: отрицательный контроль — 20 проверок. После применения production-миксинов через Fabric/Knot пройдены 24 проверки публикации, отмены, переноса, повторных callbacks, освобождения и слабого удержания задачи. Gradle-сборка и Vulkan-клиент с изменением блока и reload прошли. Частота исходной гонки в игре и её связь с отдельными пропавшими секциями этим CPU-доказательством не устанавливаются.

Локальное доказательство: `build/late-upload-cpu-proof-20261104/transformed/final-receipt.json`.


## Время жизни снимка завершённой компиляции

`RenderSection.lastCompileTask` сохранял `CompileTask.region` и 27 соседних SectionCopy после завершения и отмены до запуска. Теперь снимается только ссылка `region`; готовый mesh, block entities, SortState и task metadata сохраняются. Общие snapshot-данные не закрываются и не изменяются.

Работающий компилятор сохраняет аргумент до выхода. Короткий marker под существующим task monitor отделяет выполняющуюся работу от pending cancellation. Компиляция, queue, copyLock и GPU-вызовы не выполняются под новым monitor-блоком.

Штатный executor повторно ставит в очередь NPE, возникший до нормального RETURN. Поэтому для такого незавершённого повтора region сохраняется; отмена освобождает его. После нормального RETURN native isCompleted устанавливается до очистки буферов; последующий NPE не приводит к повторному исполнению completed task. Безусловный finally-clear или обнуление работающего аргумента из cancel не используются.

Actual Fabric/Knot: 26 отрицательных и 51 production-проверка, включая latch после обоих native cancellation checks, настоящий requeue/retry, исключения и weak references всех 27 snapshot payloads. Сохранены 20/24 callback-контроля. В четырёх настоящих Vulkan-запусках на quiet seal подтверждены 7597 completed tasks и ноль region references; pending, missing и upload counts равны нулю. Это доказательство освобождения ссылок, не измеренный объём экономии RSS или FPS.

Локальные артефакты: `build/section-region-retention-20261104/transformed/final-receipt.json`, `build/shadow-snapshot-memory-audit-20261104/audit.json`. Идея явного окончания временного контекста сопоставлена с [Sodium ChunkBuilder](https://github.com/CaffeineMC/sodium/blob/dev/common/src/main/java/net/caffeinemc/mods/sodium/client/render/chunk/compile/executor/ChunkBuilder.java) и [BlockRenderCache.cleanup](https://github.com/CaffeineMC/sodium/blob/dev/common/src/main/java/net/caffeinemc/mods/sodium/client/render/chunk/compile/pipeline/BlockRenderCache.java). Код не переносился; собственный вариант сохраняет native NPE retry.
