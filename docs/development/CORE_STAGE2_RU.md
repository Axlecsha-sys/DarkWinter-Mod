# DarkWinter Core — самостоятельное окно, этап 2

Это описание завершённого этапа 2. Текущее продолжение — [этап 3: DarkWinter_Test, изменение мира и сохранение](CORE_STAGE3_RU.md). Корневой Start-DarkWinter-Core.cmd теперь предпочитает клиент этапа 3.

Дата: 06.11.2026. Проверено Windows x64, AMD Radeon RX 7600 XT, Vulkan, C++20 / Zig 0.14.1.

## Текущее состояние

Создан отдельный оконный клиент **DarkWinter.exe**. Он загружает импортированный DWV,
подготавливает секции в четырёх C++-потоках и рисует мир вычислительным шейдером Vulkan.
В этом процессе нет Minecraft, Fabric, JVM, Java GC или встроенного MinecraftServer.
Существующая Fabric-игра продолжает работать своим прежним конвейером.

Это законченный технический просмотрщик выбранной локации. Персонаж, столкновения,
симуляция, взаимодействия, изменение мира, погода, звук, стриминг большого мира и
полный перенос игровых сохранений ещё не реализованы в самостоятельном клиенте.

## Запуск

В проекте — двойной щелчок по **Start-DarkWinter-Core.cmd**.
Непосредственно: **build/core/client/DarkWinter.exe**.
Готовый переносимый архив: **build/core/package/DarkWinter-Core-Windows-x64.zip**:
распаковать в одну папку и запустить DarkWinter.exe, сохранив соседние файлы.

Для запуска нужны Windows x64 и драйвер Vulkan 1.1+. JDK, Python, Zig, Minecraft,
Fabric, LWJGL и компилятор шейдеров при запуске EXE не нужны.

| Управление | Действие |
| --- | --- |
| W/A/S/D | Свободный полёт камеры |
| Space / Ctrl | Вверх / вниз |
| Правая кнопка мыши | Осмотр мышью |
| Стрелки | Поворот камеры |
| Shift / колесо | Ускорение / выбор скорости |

При потере фокуса отпускаются удерживаемые клавиши и захват мыши. При сворачивании
отрисовка приостанавливается; изменение размера пересоздаёт только ресурсы вывода.

## Что означает «воксели» здесь

Автор уточнил: важна идея способа отрисовки из
[видео POF, с 25:13](https://www.youtube.com/watch?v=0kq-CTT4WiI&t=1513),
а не масштаб вокселей, разрушения или игровой процесс Teardown.
Фрагмент 25:05–29:56 подтверждён русской расшифровкой vidIQ.

Мир остаётся сеткой блоков. Луч каждого пикселя читает эту сетку и находит видимую
поверхность. Пустые области пропускаются через пять уровней занятости секции.
Подробные формы столбов, ограждений и проводов представлены общими шаблонами,
повторно используемыми всеми экземплярами состояния.

Внутри сложного блока луч обходит BVH его исходных полигональных форм. Это гибрид
воксельной сетки и общих шаблонов геометрии, без сборки или растеризации мешей чанков.
Формы не переводятся в грубые микрокубики. Аппаратные RT-ядра не используются.

**Полноценного DAG мира пока нет.** Иерархия занятости секции и BVH формы не являются
общим DAG. Число пикселей задаёт число первичных лучей; стоимость каждого луча
также зависит от пройденных узлов, форм, дальности и освещения. Размеры памяти,
названные в видео, не считаются универсальной гарантией для DarkWinter.

## Конвейер и владение

1. Ядро проверяет DWV и готовит неизменяемые секции с ревизиями.
2. Клиент строит ограниченную таблицу секций и переносит её, ячейки и занятость на GPU.
3. Общие формы и текстуры загружаются один раз. В кадре нет сборки геометрии мира,
   чтения сохранения или выделения новых буферов сцены.
4. Vulkan compute выполняет проход по сетке, пропуск пустот и пересечение формы.
   В прототипе есть текстуры, направленный свет, жёсткие тени, дымка и простое небо.
5. Изображение копируется в swapchain. Два кадра имеют отдельные ресурсы и fence;
   семафоры завершения вывода привязаны к изображениям swapchain.
6. Завершение дожидается GPU, затем освобождает Vulkan-ресурсы и C++-ядро.

Загрузка мира, подготовка в пуле и GPU-отрисовка выполняются разными исполнителями.
Последовательная обработка событий окна и отправка команд GPU остаются обычной
частью управления кадром. Вся игровая симуляция ещё не перенесена.

## Ресурсы и формат DWA

Снимок: 60 секций, 22 состояния, 245760 ячеек. Для отрисовки используются
3173 экземпляра непустых форм; невидимый minecraft:light не рисуется.

Экспортёр берёт подробные формы из собственного furniture/meshes.json, а не из
упрощённых резервных block-model JSON. Сохранены повороты, части сборок, UV,
провисание трёх проводов и концевые половины пролётов на столбах.
Всего: 25 вариантов формы, 7078 общих треугольников, 2685 узлов BVH, 9 контекстных замен.

Пропущенные кодеком свойства раскрываются только для поддержанного набора:
facing=north, part=0, snowy=false; для проводов — собственные defaults. Это не
универсальная замена реестров Minecraft. Незнакомые состояния явно отвергаются.

В пакете только собственные текстуры DarkWinter. Ванильные снег и smooth_stone
получили собственные снег и бетон; их ванильные изображения не копируются.

DWA v1: заголовок DWASSET + NUL, версия, число u32, FNV-1a64 точного DWV и FNV-1a64
данных. Таблицы: варианты форм, узлы BVH, треугольники/UV/материалы, описания и
пиксели текстур, контекстные замены ячеек. Диапазоны, конечность чисел и принадлежность
узлов/замен проверяются перед передачей GPU. Это внутренний формат этапа 2.

## Проверки и измерения

Завершённый общий прогон: build/core/window-runs/20261106-223652-988.
Файлы initial.png, moved.png, final.png получены с GPU; начальный и перемещённый кадры
осмотрены. Сохранены подробные силуэты ограждений, столбов и тонких проводов.

- 180 кадров оконного теста; 1392 сравнения попаданий GPU с независимым перебором
  треугольников на CPU. Материал и расстояние совпали, ошибок 0.
- Есть адресные лучи по видимым материалам; все семь состояний проводов присутствуют
  в изображении. Обычная сетка проверок дополняет адресные лучи.
- Два изменения размера, сворачивание/восстановление, движение через обработчики
  событий клавиш; состояние камеры изменилось.
- 600 кадров отдельного запуска с PATH только Windows System32, без JAVA_HOME/JDK.
  В PE-импортах и списке загруженных модулей нет Java/JVM.
- Восемь повреждённых или несовместимых DWA отвергнуты до создания окна.
- Копия DWV не изменилась. В архиве проверяются CRC, пути, точные хеши бинарников и
  отсутствие Java/DLL-рантаймов. Проверяются учитываемые исходники и git diff --check.
- Повторно прошли 306547 нативных assertions этапа 1, 179 FFM-проверок и обычный build.

Безопасная оптимизация: несколько материалов используют один и тот же исходный
PNG. Теперь его пиксели хранятся один раз. Объём статических ресурсов на GPU сократился
**с 34888292 до 13916692 байт**, три контрольных PNG совпали побитово. Данные мира
занимают 1018624 байта. Это не полный расход VRAM: изображения вывода, swapchain,
тестовые буферы и память драйвера учитываются отдельно.

На неподвижной исходной камере при 1280×720, без VSync, после 30 начальных кадров:

| Показатель | Медиана, мс | p95, мс |
| --- | ---: | ---: |
| GPU: вычислительный проход, 570 измерений | 1,34808 | 1,38684 |
| CPU: вызов draw с ожиданием кадра и present, 569 измерений | 1,5233 | 2,2421 |

Это малая разреженная локация, один прогон и отдельные интервалы конвейера.
Драйверные оверлеи не отключались. Эти значения не означают FPS всей будущей игры
или выигрыш относительно Minecraft. В повторном прогоне build/core/package-checks/20261106-224640-141 медиана GPU была
0,80792 мс, p95 — 1,4088 мс. Разброс между запусками дополнительно ограничивает выводы.
В оконном тесте с чтением попаданий и сменой камеры измерения другие. Vulkan validation layers в среде отсутствовали; значение
validationErrors=0 не заменяет проверку слоями. Физическая мышь отдельно не проверена.

## Сборка и продолжение

Из корня проекта, с JDK 25, Python и уже установленным проверенным Zig 0.14.1:

~~~powershell
.\gradlew.bat coreBuildClient
.\gradlew.bat coreInspectClientPackage
.\gradlew.bat corePackageClient
.\gradlew.bat coreRunStandalone
~~~

Обычный build не собирает этот EXE. Шейдер компилируется существующим shaderc из
зависимостей проекта только при сборке. Заголовки Vulkan-Headers 1.3.296 загружаются
из официального репозитория по закреплённым SHA-256, лицензии включены в архив.

Пределы просмотрщика: Windows x64; до 4096 секций; ограниченная таблица секций;
координаты секций [-2048,2047]; до 64 МиБ DWA; луч до 512 блоков. Пока поддержан
проверенный дорожный набор состояний, а не все 134 каталожных объекта.
Изменяемый мир и редактирование ещё не подключены к кадру.

Следующее содержательное направление: обновление изменённых секций и общих форм,
бюджеты стриминга, более крупная сцена, затем оценка DAG на реальных данных.
Новые этапы симуляции и переноса игрового состояния требуют отдельной реализации.
