# Аудит C++-экспериментов

Дальнейшие направления: [DVCPP-001–DVCPP-007 — очередь и критерии](DVCPP_PLAN_RU.md).

Проверены реальные исходники ветки develop/с++: C++ ABI, FFM-адаптеры, перехваты Minecraft/Fabric Indigo, самостоятельные проверки и сохранённые игровые отчёты. Это аудит двух узких экспериментов, а не перенос игрового движка на C++.

## Что реально перенесено

- /dwvoxel: C++ вычисляет маски видимых граней для сетки 18³; применяется только безопасное отрицательное решение для ограниченного списка обычных блоков.
- /dwmesh: C++ записывает окончательные BLOCK-вершины из уже вычисленных Minecraft/Indigo данных. Выбор моделей, освещение/AO, world generation, visibility graph и GPU upload остаются у игры.
- DLL собирается отдельно и не включается в mod JAR. Обычная сборка не требует C++-компилятора; VANILLA остаётся default.

Само ядро не хранит указатели, не имеет общего изменяемого состояния и проверяет пределы/индексы до записи. Scratch раздельный по workers; borrowed output используется синхронно после reserve, до следующего возможного перемещения буфера. Выгрузки DLL под работающими потоками нет. В проверенном пути ошибок индексации не обнаружено; это не доказательство корректности любого стороннего native-модуля.

## Исправлено

1. Публичные probe/probeEncoded принимали физически маленький MemorySegment вместе с большой объявленной длиной. Native проверял числа, но не мог узнать реальную Java-границу. Добавлены проверки области памяти, lifetime, потока, native-адреса, записи и выравнивания uint32-входов до downcall. NULL и неправильные числовые параметры по-прежнему проверяются настоящими C guards. Основные pack/packEncoded не менялись. Добавлены 20 отрицательных случаев и допустимые read-only inputs/невыровненный byte-output.
2. Поиск библиотеки старого voxel-пути учитывал только DLL/SO. Добавлен macOS dylib. Исполнение на macOS не проверялось.
3. При выключенном эксперименте каждая сборка создавала Scope и обновляла таймеры/счётчики. Добавлен ранний обход контекста, когда оба эксперимента отключены. Explicit override, replay, активное сравнение и вложенный контекст сохраняют прежний путь. Mixin-перехваты всё ещё имеют стоимость; нулевой overhead не заявляется.
4. complete отчёта мог оставаться true, даже если C++ реально не был использован во всех измерениях. Теперь нужны native batches во всех пяти CPP-проходах без fallback; byteParity остаётся отдельным свойством.

## Что показали исходные игровые записи

Три завершённых отчёта сравнивают 12 реальных секций. Во всех зафиксированы byteParity и фактические native calls. В последнем отчёте chunk-mesh-2368fe54-eb44-464d-ac20-1d8fde6dd836 медианы полной сборки:

| Секция | VANILLA | CPP_PACKED |
| --- | ---: | ---: |
| -2, 3, 24 | 1,652 мс | 1,907 мс |
| -6, 5, 27 | 1,855 мс | 1,761 мс |
| 1, 4, 26 | 0,427 мс | 0,506 мс |
| 0, 4, 25 | 2,693 мс | 2,711 мс |

Устойчивого ускорения полного сборщика эти данные не показывают. Измерения короткие и диагностические; это не FPS или сравнение с нетронутым vanilla-бинарником. Ранний отчёт с нулём образцов и timeout сохранён как неуспешный.

В журнале обычного CPP-режима есть 1348 сборок с нулём packedQuads/nativeBatches. Число sections учитывает и сборки без подходящей геометрии. Одних этих счётчиков недостаточно, чтобы отличить пустые/неподходящие секции от отказа eligibility. Ошибка FFM сама по себе не объясняет ноль packedQuads: этот счётчик увеличивается до вызова C++. Утечка постоянного VANILLA override при replay не найдена. Универсальный диагноз для этой записи не заявляется.

## Проверки и ограничения

Повторно прошли blockMeshVerify: 384 template + 256 Indigo пакетов, byte oracle, конкурентные вызовы, guards и проверки физических сегментов. voxelFacesVerify: 264 сцены. Бюджет DV-011: 12 сценариев, 38 243 assertions. Финальный native client regression и публикационная сборка фиксируются в отчёте DarkWinter Lab.

Автоматическая публикация DLL для разных ОС/архитектур, native sanitizer/fuzz прогоны и переносимость всех resource packs не реализованы. Source identity включает исходники ядра, но сама по себе не доказывает соответствие внешней DLL этому исходнику; точный hash проверенной DLL сохранён в локальном evidence. Java fallback не восстанавливает процесс после повреждения native памяти.

Финальный штатный клиент Vulkan открыл только DV_CPP_AUDIT_20261101 — новую копию стенда. До сравнения обычные worker builds зарегистрировали 114 native batches и 58 368 packedQuads. Новый compare 4 завершился без ошибок: четыре byteParity, во всех 20 измеренных CPP-вызовах есть native batch и нет fallback. Отчёт: run/performance-reports/chunk-mesh-d11cf685-a83d-4ed3-b72a-c55a5d05c7b6.json. Эти числа подтверждают подключение и корректность на выбранных секциях, не устойчивый прирост FPS. Исходный локальный режим CPP_PACKED восстановлен после диагностики, клиент закрыт штатно.

Повторный изолированный DV-019 маршрут с добавленными C++-адаптерами, но выключенным экспериментом, прошёл 14 geometry и 10 palette проверок: 4164 кадра, p99 8,168 мс, максимум 9,526 мс, без кадров >33,333 мс. Это одиночный regression-прогон, а не доказательство общего устранения микрофризов.

Для микрофризов продолжается адресное устранение подтверждённых расходов Java/чанков в DV-011/DV-019. Переключение языка без выигрыша полного пути не включается автоматически.
