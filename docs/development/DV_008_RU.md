# DV-008: сохранение метаданных тестового мира

Первый адресный этап DV-008 устраняет повторную запись неизменённых данных лаборатории. Он не заменяет систему загрузки, сжатия и сохранения чанков Minecraft.

## Изменение

Ранее saveProvenance каждые 100 серверных тиков заново сериализовал всю таблицу origins и атомарно заменял provenance.json. Context.save после действий также переписывал settings.json и island.json без проверки содержимого.

TestingOrigins учитывает реальные изменения по поколению на владеющем серверном потоке. Неизменённый autosave проверяет поколение за O(1), без обхода таблицы, сериализации и файловой операции. Значение того же размера, удаление, Undo/Redo и native/resize writers проходят через setOrigin; безопасное конкурентное чтение сохраняется через read-only live view. Подтверждается только успешно опубликованное поколение. Отсутствующая пустая таблица требует первой записи, полностью прочитанная существующая таблица начинает работу clean, ошибка загрузки не разрешает перезаписать повреждённый оригинал.

Настройки и island metadata используют отдельные кеши успешных detached JSON-снимков внутри конкретного Context. Изменение вложенных настроек, зон или высот обнаруживается сравнением содержимого. Кеш обновляется после успешного atomic write; неудачная запись повторяется. Новый Context при открытии/восстановлении мира не наследует кеш по пути от старого Context.

## Порядок фоновой записи

Native checkpoint сохраняет неизменяемый DTO и захваченное поколение origins. Пока metadata Future не завершён, обычный saveProvenance откладывает публикацию без ожидания. После успешной записи обоих файлов сервер подтверждает ровно захваченное поколение, один раз. Более новые live-изменения остаются dirty и записываются после старого снимка.

Явные bulk/STOP барьеры продолжают awaitCheckpoint. Native metadata writer по-прежнему пишет оба файла с force(true), даже если origins не менялись: sequence и история независимы от origins. Original chunk write futures, synchronize(true), публикация commit markers и порядок удаления REDO/WAL сохранены. Подтверждение origins само по себе не меняет native watermark.

## Проверка

Native Minecraft 26.3 / Fabric / Java 25, OpenGL, без GameTest timing hooks. Две независимые копии одного flat save помечены как Testing до открытия. В каждом клиенте созданы 100 000 записей origins без массового изменения блоков, затем выполнен flush и окно простоя не короче 210 настоящих серверных тиков. Исходные SHA-256 всех трёх metadata файлов одинаковы между версиями.

| Наблюдение | До | После |
| --- | ---: | ---: |
| Серверные тики окна простоя | 212 | 211 |
| Периодические вызовы saveProvenance | 2 | 2 |
| Успешные публикации provenance.json | 2 | 0 |
| Записанные байты provenance.json | 6 075 954 | 0 |
| Длительность двух вызовов | 35,196 / 36,164 мс | 0,0119 / 0,0051 мс |

Содержимое provenance/settings/island в окне простоя осталось побайтово одинаковым. Байты в таблице — суммарный размер успешно опубликованных файлов, не физический трафик накопителя. Это два наблюдения конкретного пути сохранения; они не доказывают общий прирост FPS/TPS. Дополнительные проверки ниже выполнены только на исправленной версии.

Дополнительный native прогон подтвердил:

- clean Context.save и действие с уже выключенными модулями не публикуют metadata;
- реальное переключение wind записывает только settings; изменение высот — только island;
- однократная ошибка Files.move для island и provenance сохраняет прежний target, удаляет temporary file, а повторная попытка публикует изменение ровно один раз;
- контейнер с 13 алмазами проходит batch → Undo → Redo с точным типизированным NBT и категориями;
- настоящий native checkpoint удерживается перед публикацией старого снимка A; после live-изменения B обычный save возвращается без ожидания за 0,0183 мс; после release и реального chunk flush B остаётся на диске;
- пять изолированных recovery preflight случаев сохраняют исходные данные: частично испорченная provenance, испорченная история, неверная подпись WAL, конфликт одной из ячеек до любых записей и отсутствующая ссылка документа;
- штатное закрытие, фактический остановленный archive capture и повторное открытие восстанавливают все 100 002 origins, точные Undo/Redo IDs и оба полных контейнерных NBT.

Standalone state checks также прошли: 101 059 assertions по поколениям, no-op, старым ACK, read-only views, доступу из другого потока, переполнению, JSON aliasing и повторению неудачной записи. Значительная часть счётчика — повторные проверки idle; это не нагрузочный FPS-тест.

## Evidence и границы

Локальные отчёты: build/run/dv008Native-before-20261031-210005-953/dv008-evidence/report.json и build/run/dv008Native-after-20261031-211222-900/dv008-evidence/report.json. Приватные tests/dv008-state, tests/dv008-client и инструменты не входят в публикацию.

Source identity до: 3da35103dfa9a3f571dd819b2b551dcf773dc0bdc17280d09a209d342c59114d; после: e0218bd51bfb4c7c314e0799ec24a2234c647a8ab5d2977549976f7475b4b5a2. Неиспользуемые новые helper уже присутствовали в исходном стенде; прежний production путь оставался без изменения. Identity публикационного JAR совпадает с проверенной исправленной сборкой.

Физический resize острова в этом прогоне не выполнялся: fixture использует настоящий flat generator. Его writer переведён на тот же проверенный setter, но полная resize-регрессия остаётся отдельной проверкой. Принудительное завершение процесса/отключение питания, отказ второго файла metadata worker или chunk future, восстановление из материализованного checkpoint и valid-SHA unsupported document-content не проверялись. Инъекция AccessDenied — управляемый отказ перед move, не реальная блокировка антивирусом. Повторно открыт исходный сохранённый мир; archive capture отдельно проверяет получение остановленного снимка. Preflight-отказы в изолированных подпапках не являются доказательством всех вариантов crash recovery.

Сериализация и сравнение settings/island всё ещё выполняются при Context.save. Сериализация изменённой большой origins, журнал действий, компрессия чанков и native history checkpoint не оптимизировались этим этапом. Следующая адресная задача по очереди — DV-018: подтвердить профилем и сократить временные объекты; фундаментальная тема IO DV-008 остаётся шире этого изменения.
