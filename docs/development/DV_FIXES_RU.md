# DV: архитектура и производительность

32 направления закреплены в исходном порядке: DV-001–DV-032. Очередь определяется приоритетом и измерениями, номер не меняется. Minecraft 26.3 / Fabric / Java 25, без сторонних игровых модов.

Кандидаты на перенос вычислительных ядер в C++ имеют отдельные номера DVCPP-001–DVCPP-007: [приоритеты, связь с DV и критерии проверки](DVCPP_PLAN_RU.md). Перенос языка не закрывает соответствующий DV автоматически.

P0: измерения и подтверждённые пики задержек. P1: локальные оптимизации после профиля. P2: крупные отдельные системы. P3: переработка ядра или новые правила игры. Статус «открыто» сохраняется, пока конкретные критерии не проверены; каркас и компиляция не означают готовность.

## Фактическая исходная база

В 26.3 уже есть worker meshing, динамическая очередь секций, visibility graph, MDI, асинхронные стадии generation/light. Свет уже дедуплицирует checkBlock. PlayerChunkSender уже учитывает расстояние, квоты и ACK/backpressure. ServerTickRateManager поддерживает изменение tick rate, а render interpolation уже существует. Render states также уже применяются. Эти механизмы не добавляются повторно под видом исправлений.

Подтверждённая первая точка: LevelRenderer.compileSections вызывает compileSync подряд для NEARBY/playerChanged без общего бюджета серии. DV-017 ограничивает эту серию, сохраняя native compileAsync для остатка. Это не частичные meshes: DV-011 остаётся отдельной задачей. Одно синхронное перестроение может само превышать мягкий бюджет; абсолютная гарантия длительности кадра не заявляется.

Source-аудит DarkWinter также выявил кандидаты: полные origins scans в TestingServer каждый tick; idle-перезапись provenance каждые 100 ticks; ежесекундные обходы TestingScene; полный OnlineBridge DTO с новой revision даже без содержательных изменений. Эти наблюдения ещё не являются измеренным выигрышем. Нельзя убирать fsync native journal ради FPS: сохраняется crash-safe REDO.

Pipeline Guard, sky/fog/OIT, календарь, движение, погода, обычные миры и серверная authority сохраняются. Производительность оценивается по конкретной причине и одинаковым сценам. Render-only benchmark с замороженным сервером не доказывает рост TPS или ускорение AI.

Опорные официальные сведения: [26.3 Snapshot 2: OIT и поведение мобов](https://www.minecraft.net/en-us/article/minecraft-26-3-snapshot-2), [Fabric для 26.3](https://www.fabricmc.net/2026/09/15/263.html). Точная реализация проверяется по локальному 26.3 source/bytecode.

## Git

Общая ветка: develop/dv-fixes. Одна задача: develop/dv-fixes-dv-xxx. Git не допускает одновременно refs develop/dv-fixes и develop/dv-fixes/dv-xxx из-за конфликта файла/каталога, поэтому используется дефис.

Каждая проверенная задача коммитится кратко «что было → что стало» и сливается только в общую ветку. Main остаётся без DV-изменений до завершения программы. Частичные улучшения внутри направления описываются отдельно и не закрывают весь пункт автоматически.

## Статус

DV-017: первое адресное исправление завершено — ограничена серия приоритетных sync rebuild и закрыта воспроизведённая гонка отменённого EMPTY. Реальные OpenGL/Vulkan проверки прошли. [Изменение, измерения и ограничения](DV_017_RU.md).

DV-032: первая версия измерительного контура завершена — ограниченный collector, отдельные CPU/GPU/tick/JVM каналы, source identity, проверка сопоставимости и native OpenGL/Vulkan matrix. [Метод, команды и границы проверки](DV_032_RU.md). Аппаратное расширение за пределами проверенной RX 7600 XT остаётся открытым. Отдельно устранена подтверждённая JFR периодическая блокировка F10: CPU/log сбор перенесён с игрового потока в ограниченный worker. [Проверка, числа и оставшиеся единичные задержки](DV_032_F10_RU.md).

DV-008: первый адресный этап завершён — unchanged provenance autosave пропускается по поколению; settings/island публикуются только при изменении содержимого. Проверены реальные ошибки atomic move, старый worker/new live ordering, Undo/Redo, preflight-отказы и штатное переоткрытие с NBT. Барьеры native журнала сохранены. [Изменение, native измерения и непроверенные сценарии](DV_008_RU.md).

DV-018: первый подтверждённый источник временных объектов устранён — entry wrappers при перечислении origins в TestingScene.sync заменены прямым key/value обходом с прежней сортировкой. Native allocation-counter delta на 100k terrain origins снизился с 4 002 928 B до 2 392 B на вызов; JFR и проверки реальной сцены/Undo/Redo прошли. [Профиль, изменение и границы](DV_018_RU.md).

DV-006: первый адресный этап завершён — порядок native chunk lease сортируется один раз на владельца. На 64 готовых опросах 4096 чанков приблизительные выделения снизились на 18,5%, среднее время prepareChunks — с 2,557 до 1,596 мс. Сохранены квоты, порядок, readiness и shared release; семь native functional-групп прошли. Общий scheduler и GPU-upload этим этапом не реализованы. [Изменение, контроль и ограничения](DV_006_RU.md).

DV-011: первый адресный этап завершён — ограничена подготовка snapshots, первоначальная non-player сборка UNCOMPILED направляется в workers, заведомо пустая копия пропускает обход 4096 ячеек. Native OpenGL/Vulkan и lifecycle-регрессии прошли. Общего выигрыша p99 на flat-маршруте не обнаружено; часть пиков совпадает с G1-паузами, причины отдельных задержек не установлены. Частичные meshes непустых секций и устранение всех микрофризов остаются открытыми. [Изменения, проверки и границы](DV_011_RU.md).

DV-019: первый адресный этап завершён — упаковка однородной native палитры больше не создаёт отбрасываемый int-массив. Реальные PackedData/codec/NBT и geometry проверки прошли; измерены оставшиеся G1-паузы и отдельные GPU/present ожидания. Для этого ПК добавлен необязательный локальный профиль запуска, публичный default остаётся SYSTEM. Полное устранение GC и микрофризов не заявляется. [Изменение, измерения и границы](DV_019_RU.md).

DV-020: первый адресный этап завершён — worker scratch отделён от lifetime DLL, добавлено безопасное retirement занятых областей, закрыты поздние выделения после disconnect. Собственные shadow GPU resources и ссылка на мир освобождаются сразу при выходе. OpenGL/Vulkan прошли по 19 lifecycle-проверок, live scratch и cached payload при idle равны нулю. Это не доказательство отсутствия всех утечек или снижения RSS/VRAM на фиксированное число байт. [Владение, проверки и границы](DV_020_RU.md).

DV-030: первый адресный этап завершён — рендер, погода и связанные solar/film gates используют один immutable presentation snapshot. Убрано чтение локальных mutable settings и создание полной сетевой settings-копии в presentation getter. На Vulkan прошли 76 weather cases, 11 групп native lifecycle/presentation контрактов и настоящий локальный Online host стенд. Это не полная изоляция ядра и не измеренное ускорение FPS. [Изменение и границы](DV_030_RU.md), [аудит архитектурной группы](DV_ARCHITECTURE_RU.md).

Остальные 23 направления открыты; широкие темы IO, временных объектов, фоновой нагрузки, геометрии, GC, frame pacing и межплатформенной производительности не считаются целиком решёнными первыми адресными этапами.
