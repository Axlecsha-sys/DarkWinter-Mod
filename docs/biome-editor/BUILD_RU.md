# Сборка и запуск редактора

[Руководство](README.md) · [Контракт профиля и IPC](../../darkwinter-biome-editor/EDITOR_CONTRACT.md)

Редактор состоит из двух частей. CMake собирает приложение C++/Qt; Gradle готовит отдельный Minecraft/Fabric backend и полный набор параметров его запуска. Сборка только одной части не даёт рабочую цепочку предпросмотра.

## Требования

- Windows x64; остальные платформы этим этапом не проверены.
- Компилятор C++20, совместимый с выбранной сборкой Qt. Локально используется MSVC.
- CMake 3.25 или новее и Ninja.
- Qt 6.8 или новее с модулями Core, Gui и Widgets. Текущая конфигурация — Qt 6.10.3 `msvc2022_64`.
- Заголовки Vulkan; локально используются Vulkan-Headers 1.4.328. Драйвер должен поддерживать Vulkan 1.2.
- Java 25 x64 и зависимости проекта Minecraft 26.3 / Fabric Loader 0.19.5.

Viewport использует `QVulkanWindow` и собственный Vulkan pipeline. При недоступном Vulkan интерфейс показывает причину; автоматического перехода на OpenGL нет. Для обычной C++-сборки компилятор шейдеров не требуется: собственный SPIR-V уже включён в исходники.

## 1. Приложение C++/Qt

Открыть Developer PowerShell для x64 MSVC и перейти в корень DarkWinter. Пути к установленным Qt и Vulkan-Headers ниже служат примером и должны соответствовать локальной установке.

```powershell
$qtPrefix = 'C:/Qt/6.10.3/msvc2022_64'
$vulkanHeaders = 'C:/dev/Vulkan-Headers/include'

cmake -S darkwinter-biome-editor -B build/biome-editor-cpp -G Ninja `
  -DCMAKE_BUILD_TYPE=Release -DDARKWINTER_BUILD_EDITOR=ON `
  "-DCMAKE_PREFIX_PATH=$qtPrefix" "-DVulkan_INCLUDE_DIR=$vulkanHeaders"

cmake --build build/biome-editor-cpp --parallel 2
ctest --test-dir build/biome-editor-cpp --output-on-failure
```

Вместо `Vulkan_INCLUDE_DIR` поддерживается `DARKWINTER_VULKAN_HEADERS`. Для тестов документа, IPC и математики камеры без сборки GUI можно указать `-DDARKWINTER_BUILD_EDITOR=OFF`. CTest не запускает Minecraft.

CMake отдельно определяет фактический локализованный префикс MSVC `/showIncludes`, чтобы Ninja отслеживал изменения заголовков. При смене компилятора или набора Qt следует заново сконфигурировать отдельный build-каталог.

## 2. Точный игровой backend

Из корня проекта:

```powershell
.\gradlew.bat prepareBiomeEditorWorker
```

Задача компилирует worker, готовит ресурсы и создаёт `build/biome-editor/worker-launch.json`. Это локальный файл с абсолютными путями к Java, classpath, рабочему каталогу и параметрам Fabric. После переноса проекта или изменения зависимостей его нужно подготовить заново.

Рабочие файлы backend находятся в `build/biome-editor/runtime`, отдельные IPC-сеансы — в `build/biome-editor/ipc/session-*`. Обычный каталог `run` и пользовательские сохранения не используются для сцены редактора.

Worker запускается самим приложением с параметром `-Ddarkwinter.biomeEditor.ipc=<сеанс>`. Прямой запуск `runBiomeEditorWorker` без собственного сеанса IPC не является обычным способом работы.

## 3. Запуск

Добавить `bin` выбранной Qt в PATH текущего процесса либо подготовить приложение штатным `windeployqt`. Затем:

```powershell
$env:PATH = "$qtPrefix/bin;$env:PATH"
.\build\biome-editor-cpp\DarkWinterBiomeEditor.exe --darkwinter-root F:/DarkWinter
```

В окне нажать «Запустить генератор». Путь проекта можно изменить до запуска backend. Остановка генератора отправляет ему отдельный запрос завершения.

## Как проходит точная генерация

1. C++ проверяет профиль и атомарно публикует запрос с revision.
2. Worker создаёт datapack через штатные кодеки Minecraft и открывает собственный новый мир.
3. Штатный noise-генератор строит рельеф. Общая Java-feature применяет воду, покрытие, растения и блочные операции только во время генерации новых чанков.
4. Minecraft создаёт ограниченные снимки секций; отдельный CPU-исполнитель вызывает штатный SectionCompiler. Экспортируются настоящие vertex/index buffers, stitched atlas и 16×16 lightmap.
5. C++ один раз проверяет размеры, индексы и SHA-256 и загружает сцену в Vulkan. Камера, масштаб и кисть используют сохранённые GPU-ресурсы без RPC. Освещение обновляется маленьким отдельным пакетом.

Параметры рельефа для предпросмотра и datapack формирует один Java-код. C++ не рассчитывает отдельную визуальную копию местности. Навигация не создаёт новую сцену. Изменение окружения передаёт lightmap, изменение cutY требует новой компиляции. Во время генерации предыдущая сцена остаётся доступной.

## Проверки и диагностика

- CTest проверяет JSON-профиль, историю, границы данных, IPC и математику камеры. Эти проверки не подтверждают работу Minecraft.
- `--ui-smoke <каталог>` проверяет собственное окно и Vulkan viewport. Параметр `--smoke-image <PNG>` использует явно диагностическое статическое изображение.
- `--scene-smoke <каталог>` проверяет реальный вывод Vulkan, порядок цветов, пять сбросов scene/resource ID, смену размеров и отсутствие работы при простое. Синтетическая калибровка явно отделена от генерации мира.
- `--worker-smoke F:/DarkWinter <каталог>` запускает настоящий backend, четыре режима освещения и 120 секунд навигации; затем проверяет шесть мазков, включая запрос во время генерации, Undo/Redo и native-профиль экспорта. `--worker-smoke-seconds 12` сокращает только диагностику и не даёт полного PASS по длительному прогону.
- В IPC-сеансе доступны `state.json`, `scene.json`, `lighting.json` и immutable-файлы геометрии/атласа/lightmap. Формат описан в [протоколе сцены](SCENE_PROTOCOL.md). Состояние ошибки и хвост журнала отображаются приложением.
- Старый поток RGBA сохранён только как отдельный диагностический backend-режим `-Ddarkwinter.biomeEditor.raster=true`; интерактивный редактор по умолчанию его не использует. Он не является переключателем полного постпроцессинга в локальном viewport.

Последние результаты и границы проверенной функциональности приведены в руководстве. Наличие `worker-launch.json`, успешная компиляция и корректный показ диагностического PNG не означают, что все операции и экспорт уже приняты на реальной сцене.
